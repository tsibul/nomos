# Модель данных Nomos

Статус: утверждено пользователем (вопросы 1–9 решены). Кода нет.

## 0. Главное в пяти строках

1. Акт → дерево фрагментов (до пункта/подпункта) → у каждого фрагмента редакции во времени → у редакции тексты на языках.
2. Каждая редакция знает, каким положением какого акта введена (`Изменение`).
3. Фрагмент имеет вечный внутренний `uid` и читаемый адрес `eid` в духе ELI/EUR-Lex (`art_98.par_2`).
4. Источник истины для текстов — файлы в git (свой XML с HTML-подмножеством внутри), БД — индекс, полностью пересобираемый из файлов.
5. Наш перевод привязан к хешу исходного текста; сменился исход — перевод помечен устаревшим, неизменённые предложения берутся из памяти переводов.

## 1. Сущности

Обозначения: FK — ссылка на другую сущность; `?` — необязательно.

### 1.1. Источник (`Source`)

| Поле | Тип | Смысл |
|---|---|---|
| code | строка, уник. | `eurlex`, `cylaw`, `cy-gazette`, `taxdep`, `minfin-ru` |
| name, url, publisher | строки | |
| license | строка | краткое имя или описание условий |
| terms_url | URL | где условия |
| attribution | текст | обязательная подпись при показе |
| checked_on | дата | когда проверены условия |

Лицензия нужна только для будущей публикации через сайт; на хранение не влияет (все тексты в одном закрытом репозитории, см. 3.1).

### 1.2. Акт (`Act`)

| Поле | Тип | Смысл |

| jurisdiction | выбор | `eu`, `cy`, `ifrs`, `us` |
| kind | выбор | закон, подзаконный акт (ΚΔΠ), директива, регламент, имплементационный регламент, стандарт, инструкция, циркуляр, решение |
| number, year | строки | как в официальном обозначении (`95(I)`, `2000`) |
| date_adopted | дата | дата принятия/документа |
| published_on | дата | дата официальной публикации |
| published_in | строка | `OJ L 347, 11.12.2006`, `Ε.Ε. Παρ. Ι(Ι) Αρ. 4982` |
| in_force_from | дата? | вступление в силу (по умолчанию для всех положений) |
| in_force_rule | текст? | если дата задана правилом («см. ст. 413») |
| repealed_on | дата? | |
| eli, celex | строки? | внешние идентификаторы |
| part_of | FK Act? | например, МСФО (IAS 16) внутри приложения Регламента 2023/1803 — см. вопрос 7 |

Заголовки акта — в языковых версиях (1.3), не здесь.

### 1.4. Языковая версия акта (`Expression`)

| Поле | Тип | Смысл |
|---|---|---|
| act | FK Act | |
| lang | `el`, `en`, `ru`… | |
| status | выбор | официальный текст / официальный перевод / неофициальный перевод / наш перевод |
| source | FK Source | откуда (для нашего перевода — `nomos`) |

### 1.5. Фрагмент (`Fragment`)

Единица структуры, у которой есть собственный номер или собственное место: часть, раздел, глава, секция, статья, пункт, подпункт, абзац без номера, отступ («—»), приложение, пункт приложения, таблица, преамбула, соображение (recital), сноска акта.

| Поле | Тип | Смысл |
|---|---|---|
| uid | строка, уник., вечная | 10 знаков base32, не меняется никогда |
| act | FK Act | |
| parent | FK Fragment? | |
| kind | выбор | `prt`, `tis`, `cpt`, `sct`, `art`, `par`, `sub`, `pnt`, `ind`, `anx`, `tbl`, `rct`, `cit`, `fnt`, `sch` (Παράρτημα кипрского закона), `def` |
| eid | строка | текущий читаемый адрес внутри акта (`art_45.par_7G`) |
| order_key | строка | ключ сортировки среди братьев (см. 2.3) |

определение (`def`): термин в статье определений; адрес `art_2.par_1.def_<ключ>`, ключ —
термин латиницей без ударений (`def_anadiarthrwsh`). Абзацы под определением — его `sub`.

Число и заголовок — в редакции (номер может измениться), `eid` — текущий кэш.

### 1.6. Прежний адрес фрагмента (`FragmentAlias`)

| Поле | Тип | Смысл |
|---|---|---|
| fragment | FK | |
| eid | строка | адрес, под которым фрагмент был известен |
| valid_from, valid_to | даты | когда этот адрес был верен |

Нужно только при перенумерации: старая ссылка «ст. 11(3)» ведёт на тот же фрагмент.

### 1.7. Изменение (`Amendment`)

Одно положение изменяющего акта, применённое к одному или нескольким фрагментам.

| Поле | Тип | Смысл |
|---|---|---|
| amending_act | FK Act | `eu/dir/2022/542` |
| amending_fragment | FK Fragment? | конкретное положение: `art_1.pnt_6` |
| kind | выбор | заменить, вставить, исключить, перенумеровать, исправить (corrigendum), базовый текст |
| published_on | дата | публикация изменяющего акта |
| in_force_from | дата | вступление в силу этого положения |
| applies_from | дата? | применение, если отличается (директивы, отсроченные пункты) |
| retroactive | да/нет | вычисляется: `in_force_from < published_on` |
| key | строка | ключ изменения внутри изменяющего акта: `<положение>:<вид>[@<дата>]` (`art_2:insert@2026-10-12`); у базового текста — `base`; уникален в пределах акта |
| marker | строка? | метка источника: `M32` EUR-Lex, номер сноски cylaw |
| note | текст? | |

### 1.8. Редакция фрагмента (`FragmentVersion`)

| Поле | Тип | Смысл |
|---|---|---|
| fragment | FK | |
| key | строка | `2022-04-06`, при совпадении дат — `2022-04-06~2` |
| amendment | FK Amendment | чем введена; для базового текста — `kind=базовый` |
| num | строка | номер как напечатан: `(7Γ)`, `Article 98a` |
| heading | строка? | заголовок на опорном языке (на прочих языках — `FragmentText.heading`) |
| state | выбор | действует / исключён (`—————`) |
| valid_from | дата? | начало действия; `null` — до 01.01.2024, не прослеживается |
| applies_from | дата? | начало применения, если отличается |
| known_from | дата | когда текст стал известен — дата публикации вводящего акта |
| valid_to | дата? | кэш, вычисляется (см. 4) |

Состав детей родителя не хранится отдельно: он выводится из того, какие редакции детей действуют на дату. Поэтому вставка `(7Γ)` не создаёт новой редакции статьи 45. Если же положение заменено целиком (ст. 98 Директивы), новые редакции получают статья и все её потомки, все с одним `Amendment` — даже если текст абзаца не изменился (перевод тогда берётся из памяти бесплатно).

### 1.10. Ссылка (`Reference`)

Извлекается из разметки текста при загрузке; в файлах хранится только разметка.

| Поле | Тип | Смысл |
|---|---|---|
| from_text | FK FragmentText | где стоит |
| anchor | строка | id ссылки в разметке (одинаков во всех языках фрагмента) |
| to_act | FK Act? | |
| to_fragment | FK Fragment? | |
| mode | выбор | `current` (действующая на дату чтения) / `at_date` / `version` |
| to_date | дата? | для `at_date` |
| to_version | FK FragmentVersion? | для `version` |
| external_url | URL? | если акта нет в базе |

По умолчанию `mode=current`, но «дата чтения» — это дата, на которую пользователь смотрит исходный текст, а не сегодня. Обратные ссылки («где упоминается») — запрос по `to_fragment`.

## 2. Идентификаторы и адреса

### 2.1. Акт

`{юрисдикция}/{тип}/{год}/{номер}`, как ELI, только ASCII:

| Акт | uid |
|---|---|
| Директива 2006/112/ЕС | `eu/dir/2006/112` (ELI: `http://data.europa.eu/eli/dir/2006/112/oj`) |
| Регламент 282/2011 (имплементационный) | `eu/reg_impl/2011/282` |
| Регламент 904/2010 | `eu/reg/2010/904` |
| Закон 95(I)/2000 | `cy/law/2000/95_I` (часть `(I)` нужна: нумерация законов идёт отдельно по частям) |
| ΚΔΠ 231/2024 | `cy/kdp/2024/231` |
| Циркуляр | `cy/circ/{год}/{номер или дата}` — по исследованию источников |
| МСФО | `ifrs/ias/16`, `ifrs/ifrs/15` (см. вопрос 7) |

### 2.2. Фрагмент

`eid` — путь от ближайшего фрагмента с уникальной в акте нумерацией (статья, приложение), без глав и разделов. Так делает EUR-Lex (`art_98` лежит внутри `tis_VIII.cpt_2.sct_2`, но адрес — просто `art_98`). Перенос статьи в другую главу адрес не меняет.

- Токены: `тип_номер`, через точку: `art_98.par_2.sub_3`, `anx_III.pnt_10c`, `art_45.par_7G`.
- Абзацы без номера нумеруются по порядку: `sub_2` — второй абзац.
- Греческие буквы в номерах транслитерируются по фиксированной таблице (Α→A, Β→B, Γ→G, Δ→D…), напечатанный номер хранится в `num`. На сайте принимается и греческое написание, с переадресацией.
- `uid` в адресах сайта не показывается; он нужен для ссылок изнутри файлов и для истории при перенумерации.

### 2.3. Вставки и порядок

Вставка `11A`, `(7Γ)` — новый фрагмент со своим `eid`; соседи не трогаются. `order_key` строится разбором номера: число с нулями + буквенный суффикс по алфавиту языка (`0007.03` для 7Γ, т.к. Γ третья), так что `7Β < 7Γ < 8`. Если разбор не удаётся — ключ ставится вручную.

### 2.4. Перенумерация

Тот же `uid`, новый `eid`, старый — в `FragmentAlias` с датами. Ссылки в текстах указывают на `uid`, поэтому не ломаются.

### 2.5. Адреса сайта

```
/eu/dir/2006/112/                       акт, действующий сегодня, язык по выбору
/eu/dir/2006/112/@2024-01-01/           акт на дату
/eu/dir/2006/112/art_98/                фрагмент
/eu/dir/2006/112/@2024-01-01/art_98/ru/ фрагмент на дату, язык
/eu/dir/2006/112/art_98/v/2022-04-06/   конкретная редакция
/eu/dir/2006/112/art_98/history/        все редакции и вводящие акты
/eu/dir/2006/112/art_98/ru/notes/       сомнения в переводе
```

Сайт только локальный, на машине пользователя; публичного нет. По умолчанию — действующая сейчас редакция. `@` отличает дату от `eid`: `@2024-06-01` — на дату, `@2024` — на конец года (для текущего года — на сегодня). Дата раньше 01.01.2024 не принимается. Если у фрагмента есть уже принятая будущая редакция, страница обязательно показывает пометку «с ДАТЫ — новая редакция» со ссылкой на неё; та же редакция открывается датой после сегодняшней. Параметр `?known=2024-03-01` — «как было известно на дату» (см. 4). Каждая страница самостоятельна, поэтому «открыть в отдельном окне» — обычная ссылка; «возврат» — история браузера. Отдельных сущностей для навигации не нужно.

## 3. Хранение текста

### 3.1. Решение

Источник истины — файлы в git; БД — индекс для сайта и поиска, пересобирается командой загрузки целиком. В git лежит всё содержательное: акты, структура, редакции, тексты, переводы, примечания, глоссарий. Только в БД — служебное: очередь заданий перевода, кэши, память переводов, `valid_to`.

Причина: правки видны в истории git и ревьюятся; БД можно снести и восстановить; LLM-конвейер пишет файлы, как человек.

Все тексты — в одном закрытом репозитории; открытый репозиторий проекта — только код. Предложение: закрытый репозиторий — соседняя папка `../Nomos-texts` (рядом с `Nomos`, не внутри: так его не закоммитить в открытый по ошибке), путь задаётся переменной окружения `NOMOS_TEXTS_DIR`, удалённая копия — приватный репозиторий GitHub.

### 3.2. Файлы

```
Nomos-texts/eu/dir/2006/112/act.xml   метаданные, дерево фрагментов, редакции, изменения
Nomos-texts/eu/dir/2006/112/en.xml    тексты английской версии по редакциям
Nomos-texts/eu/dir/2006/112/el.xml
Nomos-texts/eu/dir/2006/112/ru.xml    наш перевод + примечания
Nomos-texts/glossary/el-ru.xml
```

Один файл на язык акта: языки загружаются и переводятся независимо, и у каждого свой источник.

### 3.3. Формат

XML с отступом 2 пробела, внутри текста — подмножество HTML. Фрагмент для ст. 98 (сокращено):

```xml
<!-- act.xml -->
<fragment uid="k3v9q2m7xa" kind="art" eid="art_98" parent="tis_VIII.cpt_2.sct_2">
  <version key="2022-04-06" num="Article 98" amendment="eu/dir/2022/542#art_1.pnt_6"
    valid-from="2022-04-06" known-from="2022-04-06" />
</fragment>

<!-- ru.xml -->
<text fragment="k3v9q2m7xa" version="2022-04-06" from-hash="…" translator="…">
  <p>
    …в отношении поставок, указанных не более чем в семи пунктах
    <ref id="r2" to="anx_III">Приложения III</ref>.
  </p>
  <note kind="doubt" status="open" segment="2">«exemption with deductibility» — …</note>
</text>
```

Изменения, которые вносит акт, перечисляются в его `act.xml` элементами
`<amendment key=… kind=… provision=… published-on=… in-force-from=… applies-from=… marker=…>
примечание</amendment>`. `provision` — eid положения изменяющего акта. Редакция ссылается
на изменение как `amendment="<uid акта>#<key>"`. Базовый текст акта —
`<amendment key="base" kind="base">` в его собственном `act.xml`.

Разметка внутри текста: `<p>`, `<ref to=… mode=… date=…>`, `<em>`, `<strong>`, `<sup>`, `<sub>`, `<fn id>`, `<margin>` (маргиналии кипрских законов), `<table>` с `colspan`/`rowspan`, `<q>` (цитата вставляемого текста в изменяющем акте). Нумерованные пункты — не разметка, а отдельные фрагменты.

`<ref id="r1" to="art_10">`: `to` — eid фрагмента в том же акте; на другой акт —
`to="<uid акта>#<eid>"`; на акт целиком — `to="<uid акта>"`. `id` — `r1`, `r2`… по порядку
в оригинале; в переводе у той же ссылки тот же `id`.

`<text>`: необязательный атрибут `heading` (хранится в `FragmentText.heading`).

### 3.4. Django-модели

Одна модель на сущность раздела 1, поля — как в таблицах. `body` — `TextField`. Индексы: `(act, eid)`, `(fragment, valid_from)`, `text_hash`, `TMSegment.src_hash`. Полнотекстовый поиск — FULLTEXT MariaDB по `FragmentText.body` без разметки. Правка через админку не предусмотрена: правят файлы (см. вопрос 2).

## 4. Текст акта на дату

Три даты у каждого изменения: публикация (`known_from`), вступление в силу (`valid_from`), применение (`applies_from`). Они реально расходятся:

- Директива 2022/542 вступила в силу в день публикации, 06.04.2022; замена ст. 98 действует с этой даты, а вставка ст. 98a применяется с 01.01.2025 (ст. 3 Директивы). Консолидация EUR-Lex на 01.01.2024 содержит новую ст. 98 и не содержит ст. 98a — EUR-Lex ведёт консолидацию по дате применения.
- Ретроактивный закон: опубликован в июле, действует с января.

Правило выбора редакции фрагмента F на дату D по оси A (`valid` или `applies`), при знании на дату K (по умолчанию — сегодня):

1. Берутся редакции F, у которых `known_from ≤ K` и начало по оси A ≤ D.
2. Из них — с наибольшим началом по оси A; при равенстве — с наибольшим `known_from` (позднее опубликованное ретроактивное изменение побеждает).
3. Если выбранная редакция `state=исключён` или подходящей нет — фрагмента на эту дату нет.

`valid_to` не задаётся руками: это начало следующей редакции, кэш для K = сегодня. Ретроактивность видна на странице: «текст на D изменён задним числом актом X, опубликованным Y; посмотреть, как было известно на Y−1» (тот же адрес с `?known=`).

Ось на сайте — «применяется»: «действующая редакция» понимается как применяемая (так консолидирует EUR-Lex). Ось «вступило в силу» хранится и нужна для ретроактивности и директив. Будущая редакция — та, у которой начало после сегодня; она уже есть в базе, если вводящий акт принят. Исправления (corrigendum) — редакция с тем же началом, что исправленная, и поздним `known_from`: по правилу п. 2 она и побеждает.

Базовый текст на 01.01.2024: редакции, действующие на эту дату, с настоящей датой начала, если источник её даёт (EUR-Lex даёт), иначе `valid_from = null`. Более ранняя история не загружается.

## 5. Языки с несовпадающей структурой

- Дерево фрагментов одно, по опорному языку. Тексты всех языков вешаются на те же фрагменты и редакции.
- ЕС, наш перевод: структура совпадает всегда (`alignment=exact`).
- Чужой перевод с иной разбивкой (английский перевод кипрского закона, где два подпункта слиты в один абзац): текст вешается на ближайшего общего предка (`alignment=at_ancestor`); при показе фрагмента-ребёнка в этом языке показывается текст предка с пометкой. `partial` — когда перевод неполон (нет приложения).
- «Официальный текст фрагмента» при чтении перевода: тот же `uid` и та же редакция, язык со статусом «официальный текст»; если там `at_ancestor` — поднимаемся по дереву.
- Ссылки: `anchor` одинаков во всех языках одного фрагмента; цель берётся из опорного языка.

## 6. Перевод

- Единица перевода — `FragmentText` листа; внутри он делится на предложения (сегменты) для памяти переводов и примечаний.
- Перед переводом: точные совпадения предложений по `src_hash` берутся из `TMSegment`, в LLM уходят только новые; глоссарий подаётся подмножеством терминов, встречающихся во фрагменте.
- Язык-источник перевода: Кипр — греческий (английский — подсказка); ЕС — английский (греческий — для сверки).
- Новая редакция фрагмента: старый перевод остаётся при старой редакции (для неё он верен); у новой — перевода нет, пока конвейер его не сделает; неизменённые предложения переносятся из памяти.
- Правка исходника той же редакции (исправили опечатку при загрузке): `stale=да`, страница показывает «перевод мог устареть».
- Изменился утверждённый термин глоссария: тексты, где он встречается, получают примечание «проверить термин» (не `stale`).
- Второй проход LLM пишет `Note(kind=сомнение, origin=LLM)`; человек меняет `status`.

## 8. Отвергнутые варианты

- Akoma Ntoso как формат файлов — тяжёл для ручного чтения и LLM; токены `eid` взяты из того же круга, экспорт в AKN возможен позже.
- БД — источник истины, git — выгрузка — две правды при ручной правке, история правок хуже.
- Markdown — нет таблиц с объединёнными ячейками, ссылки с режимом и датой не выражаются.
- Редакции на уровне статьи целиком — каждая правка подпункта заставляет переводить всю статью.
- Редакции у родителя при вставке ребёнка — лишние версии без изменения текста.
- `eid` как первичный ключ — ломается при перенумерации.
- Числовые позиции (`position=1,2,3`) — требуют перенумерации соседей при вставке 11A.
- Своё дерево у каждого языка — ссылку «официальный текст фрагмента» не построить без сопоставления на каждом шаге.
- Хранить консолидированные версии целиком на каждую дату — дубли, нет ответа «чем введено».
- Самим применять изменения к тексту по формулировкам изменяющего акта — ненадёжно; берём консолидации источников и связываем с изменениями по маркерам.
- Одна дата «действует с» — не отличает директиву от её применения и ретроактивность.
- Память переводов в git — выводится из переводов, дублировала бы их.
