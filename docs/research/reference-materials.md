## 2. МСФО — обычные акты базы

Принимаю решение координатора без изменений, с уточнениями ниже.

### 2.1. Акты и файлы

- Один стандарт — один акт: `ifrs/ias/16`, `ifrs/ifrs/15`, `kind="standard"`,
  `part-of="eu/reg/2023/1803"` (утверждено ранее).
- Оригиналы: RTF Минфина и исходный файл английского текста — в
  `Nomos-texts/sources/ifrs/ias/16/`.
- Нет `public`: тексты видны только в личной части.
- `structure-lang="en"` остаётся. Номера пунктов МСФО одинаковы в тексте IASB, в тексте ЕС и в
  переводе Минфина. Поэтому дерево строится по номерам пунктов (`par_6`, `par_5A`, `app_B.par_B12`)
  и от языка не зависит. Английский текст из EUR-Lex добавляется потом тем же деревом.
- Оригинал обязателен (решение пользователя). Основной текст — английский:
  - стандарты, одобренные ЕС, — английский текст Регламента 2023/1803 и изменяющих его
    регламентов из EUR-Lex: `<expression lang="en" status="official_text" source="eurlex">`.
    Это официальный текст ЕС, он же задаёт редакции;
  - стандарты, не одобренные ЕС, — текст IFRS Foundation: `source="ifrs-foundation"`.
    Условия доступа и использования проверяются при загрузке.
- Перевод Минфина — второе выражение: `lang="ru"`, `status="official_translation"`,
  `source="minfin-ru"`. В заголовке выражения пометка: перевод официален в РФ, а не в ЕС.
  Русский текст ложится на дерево английского по номерам пунктов.
- Стандарт, для которого оригинал не найден, не загружается: это задача на поиск
  оригинала.
- Папки: `Nomos-texts/ifrs/ias/16/{act.xml, en.xml, ru.xml}`.

### 2.2. Какие файлы не загружаются

Загружаются только тексты, действующие на 01.01.2024 или позже:

- не берём IAS 11 (заменён IFRS 15 с 2018 года);
- не берём IFRS 9 в редакции 2010 года и «учёт хеджирования» — это прежние редакции IFRS 9 (2014).

Особые случаи:

- IAS 39 берём: часть его положений ещё применяется.
- IFRS 14 загружается без `part-of`, с пометкой «не одобрен ЕС».
- Одобрен ли ЕС IFRS 18 и IFRS 19, проверяется при загрузке, вопроса пользователю нет.

### 2.3. Редакции и приказы Минфина

- Редакции задаёт английский текст ЕС. Вводящие акты (`Amendment`) — регламенты ЕС,
  изменяющие 2023/1803; для стандартов вне ЕС — поправки IFRS Foundation.
- Каждый приказ Минфина — акт-заглушка без текста: `ru/minfin/2016/98n`,
  `jurisdiction="ru"`, `kind="order"`, с номером и датой. Связь со стандартом —
  `ActRelation(kind="вводит перевод")`.
- Пометка «(в ред. …)» у пункта русского текста при загрузке убирается из текста, её
  дословный текст хранится как `source_comment`.
- Русский текст RTF — один снимок. Он привязывается к той редакции английского текста,
  которую переводит. Если английский пункт с тех пор изменён, у русского текста флаг
  `stale`, как у перевода.
- Пункт «исключён» в русском тексте сверяется с английским: исключение берётся из
  редакции ЕС.
- Шапка RTF («Приложение N 8 к приказу … от 28.12.2015 N 217н», сроки вступления в силу)
  записывается в `act.xml` как метаданные выражения `ru`, текстом стандарта она не является.

## 3. Справочные материалы — новая сущность

Машинные переводы, выжимки и таблицы — не тексты акта. Они хранятся как материалы,
привязанные к актам.

### 3.1. Материал (`Material`)

| Поле | Тип | Смысл |
|---|---|---|
| uid | строка, уник. | `ref/cy/2025/si-self-employed-rates`, `ref/cy/mt/law-2000-95_I` |
| kind | выбор | машинный перевод / выжимка / таблица / памятка |
| title | строка | |
| lang | язык | `ru` для всех нынешних |
| origin | выбор | машинный перевод (сервис) / модель ИИ (какая) / официальный орган / пользователь |
| origin_detail | строка? | например, «бесплатная модель, название неизвестно» |
| source | FK Source? | для таблиц — орган, выпустивший таблицу |
| original_url | URL? | |
| as_of | дата | на какую дату верен: снимок CyLaw, дата выжимки |
| period | строка? | срок, на который рассчитан: `2025` для таблиц |
| review | выбор | не проверен / на проверке / проверен / проверен с исправлениями / отклонён |
| checked_by, checked_on | строка, дата? | кто и когда проверил (сессия и модель) |
| files | пути | оригиналы в `sources/ref/…` |
| original | ссылка? | оригинал, по которому материал проверяется (см. ниже); нет — «оригинал не найден» |

Оригинал (решение пользователя). У каждого материала указан оригинал:

- машинный перевод — сводный текст CyLaw этого закона: акт уже в базе, привязка с ролью
  «перевод акта», дата снимка — `as_of`;
- выжимка — акты, о которых она (привязки), и положения-доказательства её утверждений;
- таблица — официальная публикация ведомства: `original_url` и копия файла в `sources/`.
  Присланные XLSX и DOC — копии; оригинал на сайте ведомства ищется при загрузке.

Материал без найденного оригинала получает метку «оригинал не найден» и не показывается,
пока оригинал не найден.

### 3.2. Привязка (`MaterialLink`)

| Поле | Тип | Смысл |
|---|---|---|
| material | FK Material | |
| act | FK Act | `cy/law/2002/118_I` |
| fragment | FK Fragment? | если материал — о статье |
| role | выбор | перевод акта / разъясняет / рассчитан по |

Акта может не быть в базе (Cap. 113, решения Совета министров). Тогда ссылка хранит `uid` и
показывается без перехода, как в `Reference`.

### 3.3. Утверждение выжимки (`Claim`)

Выжимка проверяется не целиком, а по утверждениям.

| Поле | Тип | Смысл |
|---|---|---|
| material | FK Material | |
| n | число | номер утверждения в выжимке |
| status | выбор | не проверено / подтверждено / исправлено / опровергнуто / нет источника в базе |
| evidence | FK Fragment + дата? | положение, которым подтверждено, на какую редакцию |
| evidence_url | URL? | официальная страница, если в законе нет (например, решение о сроке TD7) |
| correction | текст? | верная формулировка, если исправлено |
| comment | текст? | |

### 3.4. Формат XML

```
Nomos-texts/ref/cy/abstract/paye/material.xml
Nomos-texts/sources/ref/cy/abstract/paye/PAYE.odt
```

```xml
<material
  uid="ref/cy/abstract/paye"
  kind="abstract"
  lang="ru"
  origin="ai_model"
  as-of="2026-01-01"
  review="in_check">
  <title>PAYE: удержание налога работодателем</title>
  <original act="cy/law/2002/118_I" />
  <link act="cy/law/2002/118_I" role="explains" />
  <link act="cy/law/1978/4" fragment="art_50" role="explains" />

  <body>
    <p>
      <claim n="1" status="confirmed" evidence="cy/law/2002/118_I#art_…@2024-01-01">
        Работодатель удерживает налог из зарплаты и перечисляет его…
      </claim>
    </p>
    <p>
      <claim n="7" status="corrected" evidence="…">
        <orig>Штраф €150 с 1 января 2026 года…</orig>
        <fix>…</fix>
      </claim>
    </p>
  </body>

  <cites>
    <cite n="1" url="…">как в выжимке</cite>
  </cites>
</material>
```

- Машинный перевод: `<body>` разбит на статьи по заголовкам — `<part fragment="art_45">`.
  Утверждений в нём нет, проверке он не подлежит, `review="not_checked"` навсегда.
- Таблица: `<body>` содержит `<table>`, оригинал XLSX или DOC лежит в `sources/`.
  `period="2025"`, `<original url="…" />` — страница ведомства.
- Ссылки `[1, 2]` в выжимках превращаются в `<cite>`; источник выжимки ещё не доказательство.

### 3.5. Показ

- Страница акта: блок «Справочные материалы» — список с видом и статусом. Если материал
  привязан к статье, у статьи значок со ссылкой.
- Общий раздел `/ref/`: фильтры по виду, акту, статусу, году. Страница материала — `/ref/{uid}/`.
- Метки на каждой странице материала:
  - «Машинный перевод CyLaw на {as_of}, не проверен»;
  - «Выжимка модели ИИ — проверено {k} из {n}»;
  - «Таблица на {period}».
  - «Оригинал не найден» — материал не показывается.
- «Мог устареть»: у привязанного акта или статьи есть редакция с началом позже `as_of`.
  Вычисляется так же, как `stale` у перевода.
- Выжимка показывается, только когда `review` — «проверен» или «проверен с исправлениями»
  (решение пользователя). На странице опровергнутые утверждения зачёркнуты, рядом
  исправление; подтверждённые ведут на положение закона.
- Машинный перевод статьи можно открыть рядом с нашим переводом («сравнить»). Сессиям
  перевода он даётся только как подсказка, не как источник.

### 3.6. Кто и как проверяет выжимки

- Проверяет сессия Claude Code пачкой, как перевод. Модель — Sonnet (проверка по списку шагов).
  Утверждения, которые Sonnet не решил, разбирает Opus. Пользователь не проверяет:
  законодательные вопросы ему не задаются.
- Шаги на одну выжимку:
  1. Разбить текст на утверждения и записать `<claim>` со статусом «не проверено».
  2. По каждому утверждению найти положение в базе: оригинал `el` и наш `ru`, редакция на
     `as_of` и на сегодня. Указать `evidence`.
  3. Сверить числа, сроки и формы дословно. Совпало — «подтверждено». Расходится —
     «исправлено» с `<fix>` по тексту закона. Неверно в целом — «опровергнуто».
  4. Положения в базе нет — «нет источника в базе», допускается `evidence_url` только на
     официальную страницу (gov.cy, Tax Department). Ссылки выжимки `[1]` доказательством
     не считаются.
  5. Выставить `review`. «Проверен» ставится, если не осталось «не проверено» и
     «нет источника»; если исправления были — «проверен с исправлениями». Если опровергнуто
     больше половины — «отклонён», такая выжимка не показывается.
- Если в выжимке упомянут акт, которого нет в базе (Cap. 113, PAYE-регламенты), выжимка ждёт
  загрузки этого акта. Это задача координатору, а не вопрос пользователю.

## 4. Что внесено в модель (`docs/design/data-model.md`)

- Источник `ifrs-foundation`.
- `Act.jurisdiction` += `ru`; `Act.kind` += приказ (акт без текста).
- `ActRelation.kind` += «вводит перевод».
- Абзац о стандартах МСФО: оригинал на английском, перевод Минфина — `ru`.
- Справочные материалы: `Material`, `MaterialLink`, `Claim` (раздел 1.14).
- Файлы: `Nomos-texts/ifrs/…`, `Nomos-texts/ref/…`, оригиналы —
  `Nomos-texts/sources/{ifrs,ref}/…`.

## 5. Отвергнутые варианты

- Машинный перевод CyLaw как выражение `ru` закона — у закона уже есть наш перевод.
  Второй русский текст со статусом «неофициальный» путал бы, а качество машинного перевода
  ниже.
- Выжимки как `Note` к фрагментам — у выжимки свой текст, источники и срок; к одной статье
  она не сводится.
- Проверка выжимки целиком одной отметкой — не видно, что именно неверно.
- Перевод Минфина как единственный текст МСФО, с редакциями по датам приказов — даты РФ,
  а не ЕС. Решение пользователя: нужен оригинал.
- EPUB как источник МСФО — дубли RTF без пометок «в ред.».
